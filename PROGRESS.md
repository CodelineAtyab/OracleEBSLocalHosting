- [x] `qm importdisk` the 300 GiB VMDK to `local-lvm`
- [x] `qm set 9000 --scsi0 local-lvm:vm-9000-disk-0` + `--boot order=scsi0`

```bash
# 1) create the golden VM shell with our exact hardware
qm create 9000 --name ebs1213-golden \
  --memory 12288 --cores 4 --sockets 1 \
  --cpu Westmere --machine pc --bios seabios \
  --scsihw lsi --ostype l26 --balloon 0 \
  --net0 e1000,bridge=vmbr0 --onboot 0

# 2) import the VMDK  (watch for the volume name, usually vm-9000-disk-0)
qm importdisk 9000 \
  "/srv/ebs-media/Oracle-E-Business-Suite-12.1.3-VISION-INSTALL-disk1.vmdk" local-lvm

# 3) attach as scsi0 + boot order + console
qm set 9000 --scsi0 local-lvm:vm-9000-disk-0
qm set 9000 --boot order=scsi0
qm set 9000 --serial0 socket --vga std

# 4) review then boot
qm config 9000
qm start 9000
```

## Known issues & fixes
- **UEK DTrace kernel panic on boot with `--cpu host`** — the OL 6.5 UEK kernel
  panics in `dtrace_psinfo_alloc` (during `execve` of init) when KVM exposes the
  host's newer CPU features. **FIX: `qm set 9000 --cpu Westmere`** (fallback
  `kvm64`). Confirmed working 2026-10-02. All EBS VMs/clones must use this.
- If Westmere ever fails, boot the **RHCK** (`2.6.32-...el6`, no DTrace) from the
  GRUB menu and make it default (`default=1` in `/boot/grub/grub.conf`), then
  remove `dtrace-modules` (`rpm -qa | grep dtrace` → `yum remove`).
- **SSH "no matching host key type found … offer: ssh-rsa,ssh-dss"** — modern
  OpenSSH disabled `ssh-rsa`; OL6 only offers the legacy types. Fix on the client:
  `ssh -oHostKeyAlgorithms=+ssh-rsa root@192.168.100.223` (add
  `-oKexAlgorithms=+diffie-hellman-group14-sha1,…` / `-oCiphers=+aes128-cbc…` if
  further negotiation errors appear). Confirmed working 2026-10-02.

### Stage 5 blocker — login page HTTP 500 — **RESOLVED 2026-10-03**
**Root cause:** the apps-tier JDBC descriptor
`$INST_TOP/appl/fnd/12.0.0/secure/EBSDB.dbc` was still the **shipped template**
(`template.dbc`), i.e. `TWO_TASK=database`, `DB_HOST=host_name`,
`DB_PORT=port_number`, `DB_NAME` commented out. OACORE therefore had no valid DB
target and returned the generic servlet 500. Everything else was already correct
— context XML (`s_dbhost=ebs`, `s_dbSid=EBSDB`, `s_dbport=1521`,
`s_webport=8000`), `tnsnames.ora`, `inst_apps_pairs.txt`, the env files — and a
repo-wide scan found `host_name`/`port_number` **only** in that one `.dbc`.

**Fix (run as `oracle`):**
```bash
. /u01/install/APPS/apps/apps_st/appl/APPSEBSDB_ebs.env
cp -p "$FND_SECURE/EBSDB.dbc" "$FND_SECURE/EBSDB.dbc.template.bak"
cd "$ADMIN_SCRIPTS_HOME" && ./adautocfg.sh appspass=apps
```
AutoConfig completed successfully (~2 min) and regenerated the `.dbc` to:
`TWO_TASK=EBSDB`, `DB_HOST=ebs.example.com`, `DB_PORT=1521`, `FNDNAM=APPS`.

## Post-MVP — student access model & next steps (planned 2026-10-03)
Two tiers — do **not** give every student a whole EBS server for functional work:
- **Functional use:** one **shared class instance** (clone `9010`) + **one EBS user
  per student**. HTML pages work in any normal browser.
- **Apps DBA practice:** one **dedicated EBS VM per student** (linked clones
  `9101–9112`) — those tasks are destructive and need exclusive `root`/`oracle`.
- **Forms screens:** one **client VM per student** (`9200` template → `9201–9212`),
  accessed via **noVNC**; required because 12.1.3 Forms is a 32-bit Java applet.

**Suggested sequence:**
1. `qm clone 9000 9010 --name ebs1213-class --full 1`, boot it, set a unique
   IP/hostname, run AutoConfig; create **one EBS user per student** in SYSADMIN →
   Security → Users and assign responsibilities. Students browse
   `http://<class-host>:8000/` (HTML only at this stage — no client VM needed).
2. Build the **client template 9200** (OL7.9 + 32-bit FF ESR52 + 32-bit Oracle
   JRE 8), verify a Forms screen opens, snapshot, then linked-clone `9201–9212`;
   give each student a Proxmox user with `VM.Console` for noVNC.
3. Linked-clone EBS sandboxes `9101–9112` (`--full 0`); cap concurrency to fit
   ~188 GiB RAM (class 12 + 12×10 + 12×2 ≈ 156 GiB → run ~8 sandboxes at once).

**Key blocker = networking/hostnames.** Each clone is a full EBS configured for
`ebs.example.com`, so many clones cannot share that name on one LAN. Either:
- give each clone a unique hostname/IP and re-run
  **`$ADMIN_SCRIPTS_HOME/adautocfg.sh`** as `oracle` (NOT `configwebentry.sh` — it
  is hardcoded to the `EBSDB_apps` context), with matching client `/etc/hosts`; or
- build the planned **`vmbr1` VLAN + local DNS** so `ebs.example.com` resolves to
  each student's own sandbox (best isolation).

**Learning tracks:** functional (navigation/responsibilities → Order-to-Cash →
Procure-to-Pay → GL/AP/AR, using the seeded Vision data); Apps DBA (filesystem
layout, start/stop, `adadmin`, `adpatch`, AutoConfig, concurrent managers,
cloning, RMAN). Reset between cohorts with `qm rollback 910x golden-clean` or
destroy + re-clone.
